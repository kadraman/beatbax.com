# Instruments

Instruments are named voice definitions. You assign them to channels and reference them from patterns and sequences. Field names and legal `type=` values depend on the active `chip`.

## Syntax {/* #syntax */}

```bax
inst <name> type=<type> [<field>=<value> ...]
```

| Concept | Notes |
|---------|-------|
| `name` | Identifier used in `channel … => inst <name>` and as a pattern token when `note=` is set |
| `type=` | Chip-specific voice (e.g. Game Boy `pulse1`, NES `triangle`, SMS `tone1`) |
| Fields | Chip-specific parameters (`duty`, `env`, `wave=`, macros, …) |

```bax
channel 1 => inst lead seq melody
```

## Shared ideas (all chips)

| Feature | Where documented |
|---------|------------------|
| Software macros (`vol_env`, `pitch_env`, `arp_env`, `duty_env`, …) | [Instrument macros](/docs/language/instrument-macros) |
| Default pitch / named drum tokens (`note=`, Game Boy `uge_note=`) | [Instrument note mapping](/docs/language/instrument-note-mapping) |

## Importing instrument libraries

Pull shared definitions from a `.ins` file so songs stay short:

```bax
import "local:lib/drums.ins"                 # CLI / desktop
import "github:user/repo/main/melodic.ins"   # CLI, desktop, browser
import "https://example.com/kit.ins"         # CLI, desktop, browser
```

Merging is **last-wins**: a local `inst` with the same name overrides an imported one. Full syntax, platforms, and security rules: [Imports](/docs/language/imports).
